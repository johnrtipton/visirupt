# Native application/event component

Own source for the observed application launch and local event-loop contract. This is part of the intended native game host, not a complete AppKit framework or proof that Cyberpunk loads. No code from the reference maciOS project is copied.

Implemented behavior: singleton NSApplication/NSApp, launch delegate and notification delivery, mask-filtered event queue with peek/dequeue/deadline, local monitor filtering/removal, responder forwarding, translated event data and dispatch to an actual host window. Guest-facing classes use associated state rather than extra instance ivars; compatibility with all guest class metadata is still a gate.

Remaining: genuine NSWindow/NSView and other imported classes, native physical input translation, cursor/menu/screen/image behavior, full responder/window dispatch, notification/lifecycle coverage, engine/UI thread ownership, display adapters and game/service libraries. UIKit/main-loop coexistence and the nullable-date contract require runtime validation against the intended guest loop. Compilation alone does not establish them. Unsupported selectors keep normal Objective-C failure behavior.

Do not put this partial component in the game loader until its missing bindings and behavior are explicitly accounted for. The separate metadata-pruning diagnostic deliberately retains the AppKit requirement and does not use these classes.

Fresh validation on October 10: ARM64 visionOS compilation passed with warnings treated as errors. A separate Foundation-only Mac executable passed 21 behavior checks: facade instance sizes, singleton, launch callbacks/notification once, translated event fields, matching/peek/dequeue/front insertion, deadline/nil expiration, current-event retrieval, monitor filtering/removal, target dispatch and worker event delivery. This does not establish physical headset input, full AppKit semantic parity, guest subclass compatibility or engine integration. Source: `scratch/cyberpunk-appkit-component/BehaviorTests.m`; logs: `context/terminal/cyberpunk-appkit-{behavior-build,behavior-run,xros-build}-20261010.log`.

Apple's documented [nil expiration contract](https://developer.apple.com/documentation/appkit/nsapplication/nextevent(matching:until:inmode:dequeue:)?changes=_10) makes nil a nonblocking poll; this was corrected from the initial indefinite wait before integration. [currentEvent](https://developer.apple.com/documentation/appkit/nsapplication/currentevent) describes the last retrieved event, so queue retrieval now records it. Peek-specific semantics and complete monitor/window behavior still require native AppKit comparison; these tests cover this component's scoped behavior.

`CPViews.h/.m` adds a separate real UIView-backed NSView facade with explicit main-thread ownership. It attaches the supplied CALayer/CAMetalLayer unchanged as a native sublayer, resizes it with the native bounds, manages replacement/visibility/container attachment and converts autoresizing margins. It adds no guest facade instance ivars. Eleven simulator checks passed for these contracts; ARM64 device-target compilation also passed. The test instantiated native views/layers but did not present or render a drawable. Window/scene management, screen coordinates, cursor/tracking/input, guest class integration and complete NSView semantics remain missing. This component is also excluded from the actual game loader.

The original service library audit requires NSApp and the two application activation notification names. These are now implemented with `cp_setActiveFromNativeScene:` to translate observed native scene state into transition notifications/delegate delivery; activation is not assumed or fabricated. Fresh simulator event checks now pass24 including suppression of duplicate notifications and active-state ordering. Actual scene integration has not yet been wired; no original service library has loaded against this component.
